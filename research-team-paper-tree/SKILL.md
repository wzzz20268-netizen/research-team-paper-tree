# 研究组论文树

从用户提供的种子论文出发，交付一份 Markdown 完整报告和一份可直接在浏览器打开的交互网页。两份成品应使用同一批已核查的资料。默认用用户的语言输出，论文保留原题。查证方法见 [检索参考](references/search-sources.md)，成品要求和生成方式见 [输出参考](references/report-output.md)。

## 识别种子论文与研究组

1. 核对题名、版本、DOI 或稳定标识、发表时间、作者和署名单位。优先看论文首页、正式出版方的通讯标注或作者信息；以作者索引补充。匹配标题有多个合理候选时，列出可区分的信息并请用户确认。
2. 逐一处理所有通讯作者，用论文当年的署名、官方组页或历史机构资料，确认作者在种子论文发表时所代表的研究组。用 ORCID、任职年份、主题和共同作者核对身份。同一组的通讯作者合并；不同组各建一棵树。作者确有多个相关组且证据支持分别参与时，都纳入并解释。共同第一作者、最后作者、单位和自动标注可提供线索，单独不足以确认通讯身份或研究组。
3. 对更名、迁移、分组或独立建组，按官方持续性证据确定边界，按每篇论文发表时的组归属判断。若机构用项目团队组织研究，且官方资料能核实团队及成员关系，可以项目团队作为追踪单位，注明采用这一边界的依据。若部分作者或组无法确认，继续处理已确认的组，把其余候选及缺失证据列为待核实。若原文与出版资料都缺少通讯标注，说明并请用户提供补充材料或指定追踪对象。

## 找全候选并逐篇判断

- 先做线索清单。从有权限查看的原文、摘要和出版页找署名与单位、参考文献与施引、问题与场景、方法或系统名、数据集或实验、基金或项目编号与资源链接。对可获得的线索判断用来查什么，报告实际用了哪些、带来了什么发现，以及重要缺口。用元数据和公开关键词补查，避免把未公开的正文交给外部搜索工具。
- 同时沿人员与组目录、原文参考文献和施引、研究内容及项目资源追踪候选。用组名旧称、跨语言名称、历史单位和早期术语补漏。从最早可核实的相关成果搜到检索日，纳入未出现在种子论文作者表里的已核实组内成果。
- 主干承载直接延续核心问题与研究路线的成果。旁支说明哪些问题、对象、方法或实验相同，哪些发生了变化。以摘要、公开正文或作者项目说明判断。主题相近、存在引用关系、存在工作继承是不同的证据强度。时间先后不足以证明技术继承。
- 论文须同时有方向关联与组归属证据。可用官方组发表清单，或结合论文署名、相关成员的任职年份、项目材料核实。仅互引、同校、同姓或单次合作的论文先当线索；归属或相关性仍未决的条目单列，不计入确认数。合作论文可进入多棵树，每棵树注明该组的参与证据，汇总时按唯一成果计数。
- 收录少量有明确联系的外组论文作为延伸阅读，从它们连到对应的本组论文。核实外组归属、关系类型、引用方向及来源。证明了引用才能画引用关系，证明了沿用或扩展才能画方法继承关系。仅有问题、方法或数据相似时，直接标明相似之处。外组成果不计入本组统计。
- 收录正式期刊论文、会议论文、预印本、综述和方法论文。先用稳定标识清除重复检索记录，再用版本关系、出版社或预印本页核对同一工作的多个版本。缺正式版本关系时，结合题名、作者、研究内容和结果核实；无法确认时保留疑点。同一成果合并为一个条目，保留各版本日期和链接。独立扩展研究另列并注明联系。
- 对可枚举的目录读到末页，或按时间段检索至耗尽；用互补来源补查新增候选，直到来源穷尽、扩展检索不再带来符合条件的论文，或遇到可说明的访问、时间或分页限制。说明实际覆盖范围及中断位置。结果多时，把完整论文树保存为 Markdown 文件，在对话中给出摘要和入口，避免只交付前若干篇。

## 交付

1. **种子论文与团队映射**。列出种子论文链接，每位通讯作者、发表时机构、研究组和归属证据，以及尚未确认的映射。
2. **阅读路线、论文树与外组关系图**。先给少量有先后顺序的推荐论文和阅读理由。每组有一棵树，按主干和具体方向展开。每个分支先用白话讲清问题、和原论文的关系、路线如何随论文推进。必要术语初次出现时用一句话解释。对种子论文和代表论文分别交代发现线索、归类理由和出处。每篇在同一棵组树中只展开一次，跨分支引用条目编号。各分支按最早可证实的公开时间由早到晚排列，保留日期精度，未知放末尾。节点保留原题、作者、日期、发表平台、版本链接和必要证据。外组论文在网页中和对应本组节点相连，在 Markdown 中给出同样的关系及证据。
3. **每组一份团队简介**。列出负责人、所属机构（区分历史与现状）、主要方向、该方向上已核实的最早和最近成果、方向持续性、具有代表性的成果及入选理由、主要合作和可核实的项目或资助。项目需能归属到该组或成员，保留项目来源与角色。若附引用量，注明数据源、查询日和所对应成果。给出可核验的事实供用户评估。
4. **覆盖和待核实项**。注明检索日、用过的数据库和组目录、时间范围、核心检索式或查询链接、已确认条目数及未覆盖原因。待核实项写明具体缺什么。可确认成果为零的研究组也要保留，说明搜索范围。
